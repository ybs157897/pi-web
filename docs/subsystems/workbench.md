# Agent 工作台

每个工作空间有一条持久的 Agent 对话。工作台的三项入口是 Agent 对话、裁决收件箱与 Bot 名册。新工作从 Agent 对话发起。工作项的召唤卡通向独立子会话，子会话展示来源、执行过程和交付，也接收用户追问。产品定义与原型位置见 [Agent 工作台提案](../../.agents/notes/proposed/feature/2026-11-18-agent-workbench.md)。

## 任务与会话

[工作台运行时](../../src/server/runtime/workbench.ts)维护 `pi-web.workbench-index` 中的工作空间索引，以及各主会话的 `pi-web.workbench`。索引按工作空间定位主会话，工作台文档保留请求、任务契约、进度、依赖、运行回执和验收结果。工作项身份独立于子会话与最新一次尝试。普通会话列表隐藏工作台主会话。

[主 Agent](../../src/server/runtime/workbench-plan.ts)用所选模型将请求转为结构化工作项，包含目标、约束、验收条件、负责人和依赖。最近消息与真实工作项提供项目背景。显式 `@` 由运行时落实，模型输出依赖只能引用较早的新工作项或同工作空间的已有工作项。既有任务的验收结果是下游执行的参考，当前请求决定执行权限。

[Bot 名册](../../src/server/runtime/workbench-bots.ts)按工作空间保存内置 Bot 的用户配置及新建 Bot。缺少匹配专长时，主 Agent 可随计划提出一个专业 Bot，宿主在同一事务内按名称或专长标识复用已有 Bot 或创建新项，再分配工作。手动编辑支持名称、职责、简介、指令、模型、权限、技能和图标。默认模型继承派发路由，技能默认全选。Bot 默认使用工作区写入沙盒，当前平台没有沙盒时默认只读。用户显式 @Bot 派发或在原子会话发新消息时，执行使用该 Bot 当前的权限。派发时显式指定的更低权限只约束该次请求和它的重试、返修。自动派发的调研与决策使用只读权限，实施工作取工作区派发权限与 Bot 配置的较低档。已启动的轮次沿用启动时的权限。子会话的单轮模型选择优先于 Bot 配置。技能选择约束会话目录及加载、校验和保存工具。

用户显式 `@通用智能体` 请求建档时，主 Agent 准备配置草案，通用智能体使用 `create_workbench_bot` 提交。只有这个工作项能看到该工具，重复提交沿用同一份回执。单纯建档请求只生成通用智能体工作项，新 Bot 留在名册供后续选用。

每项工作经 Pi Durable 后台任务归属到一条独立子会话。搜索与 `read`、`write`、`edit` 的相对路径以原工作空间为根，获用户授权的成果直接交付到那里。Shell 默认在独立工作项目录运行，可用绝对 `workdir` 切换到原工作空间。用绝对路径访问工作项目录里的临时文件。会话延续使用同一工作项目录。只读调研沿用只读工具权限，可写任务在同一工作空间串行运行。

## 调度与验收

每项工作只有一个等待对象。依赖满足后，由单进程调度器按空间容量启动工作，记录租约和心跳。投递请求标识持久化，自动重投复用同一标识。每次尝试最多执行 15 分钟，智能体真正停下来等答复时暂停计时，答复后继续使用剩余时间。超过上限时中止本轮并关闭仍待答的旧裁决，重试开启新尝试。超时、执行失败或缺少用户决定会进入需要人处理的状态。只有人工验收通过的上游交付解除依赖。

[证据采集](../../src/server/runtime/workbench-evidence.ts)在 shell 工具结算时读取结构化退出状态，覆盖直接调用、codemode 和后台 shell 轮询。文件工具记录成功读写的实际路径，即使同一脚本稍后失败也能追溯已落盘的文件。交付区按文件列出最近八个变更目标，每项打开对应文件。未记录程序校验时标为证据不足。收到结果后，用户可在收件箱验收或退回，同一轮次的裁决用尝试编号校验，退回后原子会话开启新一轮返修。

## 会话失败与恢复

[失败协议](../../src/shared/conversation-failure.ts)统一向会话快照、Agent 任务、异常邮件与 HTTP 失败响应提供错误码和恢复动作。模型访问、授权、额度及上下文错误先提示检查设置或压缩会话。可用原配置再试的情况标为 `retryable`。会话快照在自动退避期间报告下一次尝试时间，终态可报告实际执行过的自动重试次数。[错误映射](../../src/server/conversation/failure.ts)生成固定文案，轨迹记录保留分类。

[重试接口](../../src/server/app.ts)按原派发标识或工作项标识恢复，尝试编号用于拒绝重复请求。派发恢复使用保存的输入；子会话已经接到输入时，模型查看当前上下文和工作进度后续跑。用户可在恢复时选择其他可用模型。

## 裁决收件箱

[收件箱运行时](../../src/server/runtime/decision-inbox.ts)聚合同一工作空间的必要裁决与工作项结果。带理由的选择、确认和异常复用 [Interaction](interactions.md)，计划审阅沿用现有审阅记录，结果型邮件对应工作项的一次尝试。工作台子会话调用 `ask_user_question` 时必须提供 `escalation`，让收件箱获得实际原因和证据；不完整的调用返回可修复错误。

回复问题和计划沿用原会话的交互路由。用户在前台阅读对应智能体会话时，新出现的裁决、结果和异常直接在会话中处理；在这里办结的事项不会再生成收件箱副本。离开前尚未处理的事项可在收件箱找回。后台会话正常投递，原有邮件保留。会话内的验收和退回使用同一工作项及尝试编号，与邮件操作共用结算事务。

从邮件打开会话会直接进入该工作项对应的智能体详情，可以返回原信。归档与稍后提醒只更改邮件的呈现。
