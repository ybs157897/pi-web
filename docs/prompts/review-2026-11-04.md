## 六项源码借鉴及有意差异

1. **子会话**：ZCode `apps/zcode-cli/packages/core/src/subagent/tool-policy.ts` 排除计划工具，交互 broker 可转发至父会话；DSH `packages/subagent/subagent/src/depth.ts` 在执行层约束默认一层。本轮采用一次性子任务回报父级，不引入新的交互转发系统，也不声明所有 teammate 层级均被改造。
2. **WeTrack**：两侧没有对应业务模块。借鉴 ZCode workflow 的执行状态/产物分离和 DSH goal 的 revision 检查；DSH round-limit 也会 blocked，因此本轮保留该状态并细化原因，不把预算不足解释成已证实的业务根因。
3. **statechart**：ZCode Skill 描述也会截断到约 250 字符；本轮让正反触发条件完整进入该预算。DSH 的 model/user invocation policy 是可选后续能力，本轮不扩展 Skill schema。
4. **计划**：ZCode 的 planEnabled 与权限模式独立；DSH 的计划模式本身为指导性，本轮保留 pi-web 更严格的只读执行约束，不照搬其允许 write 的行为。
5. **等待**：DSH 实验性 wait_agent 只返回 timedOut/noProgress，不带答案；pi-web 已有带答案结果，不能照抄其「有运行成员才等待」。借鉴 ZCode TaskOutput 的明确结果来源与交付状态。
6. **目标**：ZCode 恢复/续跑从持久状态注入目标；DSH 的 goal 服务独立于模型工具。本轮无目标且无工具时省略，有目标时保留状态及暂停约束。

### 当前保证与限制

- WeTrack 保存与 run 更新在同一 Node 进程内按缺陷串行化并检查版本；不保证多个进程同时共用 dataDir 的 CAS。保留最近最多 5 次已保存尝试，历史正文预算约 1 MB；当前可靠结论另行保留。历史已被裁剪时报告无法核实，不伪称该 run 从未保存。
- 待处理列表每页重新读取外部列表；翻页期间外部清单变化可能造成重复或遗漏。本轮没有引入远端快照游标，也没有用真实 WeTrack 账号执行远端分析。
- `wait_agent` 返回的是带来源的近期回答预览，明确标出截断、未找到或读取失败；它不证明队友当前任务已完成，也不赋予模型访问任意 HTTP 路径的工具。
- 只读计划卡显示「确认方案」，批准后提示保留只读权限；正常可写会话仍显示实施路径。旧 goal 状态在工具缺失时保留；本轮没有改变 goal 的用户意图识别方式。

### 刀 1：给 `toolRouteInstruction` 加中文变体

### 刀 2：计划模式入口按可用性渲染

**问题**：默认请求里同时出现四种说法：
- work-policy（`src/server/conversation/work-policy.ts:138-139`）：提示用户点按钮或输入 /plan；非平凡任务「建议用户先开计划模式」。

- TODO_STEPS（`work-policy.ts:32`）：用户要方案时，把「调研→形成计划→等待确认」列成待办。
