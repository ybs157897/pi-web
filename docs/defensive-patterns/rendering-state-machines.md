# 渲染状态机（rendering-state-machines）

改 `src/web` 的渲染模型或状态机（render-model、transcript、交互卡片、子智能体面板）前先读本页；评审时逐条强制执行。四台状态机与回答区归属的现状边界见 [subsystems/rendering.md](../subsystems/rendering.md)，完整转移矩阵、缺陷编号（V1–V5）与 ego 验收记录在冻结的 [history/rendering-state-machines.md](../history/rendering-state-machines.md)。

- **工具行 live→settled 全程同一个 React key**：有 call block 的行 key 取 `tool:${block.id}`，live 阶段先到的无主 tool result 同样以 `tool:${toolCallId}` 为 key，call block 落盘配对后 key 不变、整行不重挂载（[render-model.ts:284](../../src/web/render-model.ts#L284)、[render-model.ts:289](../../src/web/render-model.ts#L289)）。key 漂移 = 整行重挂载 = 展开态 / 滚动位置 / 动画全部丢失——这就是缺陷 V3.1 的原始形态（history 文档 S3 矩阵：修复前 LIVE_ONLY 帧与 SETTLED 帧 key 必变）。
- **同一 callId 的重复无主 result 走退回 key**：`claimedCallIds` 集合防重——第一个无主 result 占住 `tool:${toolCallId}`，第二个退回 `tool-result:${message.id}`；配对成功的 result 走 callItems 分支，两种来源不得在同一 callId 上共存（[render-model.ts:283](../../src/web/render-model.ts#L283)）。丢掉防重会出现同 key 冲突或重复行。
- **answeredLocally 只许触发「不可见」**：提交答案后的本地瞬态立即藏卡是为防提交闪烁，它不得触发只读记录渲染（[QuestionComposer.tsx:95](../../src/web/QuestionComposer.tsx#L95)）；卡片可见性只认 `pending`。违例后果是已结算交互复活成常驻 Composer 上方的残留卡（缺陷 V1.1，真实模型复现截图见 history 文档 S1）。
- **子智能体面板 answer 由 spawn 边界裁定**：fork 型成员只取 spawn 边界之后的非错误 assistant 文本（边界之前是 Lead 的话音），`status=error` / `isError` 的文本跳过；没有自己答案的成员 answer 为空串，不得回填 Lead 文本（`latestOwnAnswer`，[subagent-answer.ts:11](../../src/server/conversation/subagent-answer.ts#L11)，行为由 subagent-answer 测试锁定）。违例后果即 V4.1 / V4.2：Lead 的话音或错误文本被当成子智能体的回答展示。
- **pending 交互屏障：待答 run 的正文不进回答区**：run 里存在待答 question / plan-review 时答案区恒空，模型在提问旁写的过渡文从首帧起渲染在过程区；屏障解除点是日志里最后一条交互回复 payload 之后，「已答复」与续写首 token 之间的 gap 帧不得把过渡文复活进答案区（[render-model.ts:341](../../src/web/render-model.ts#L341)、[render-model.ts:345](../../src/web/render-model.ts#L345)）。pending 判定必须读投影后的 interactions 记录（durable 工具结果的 `details.status` 冻结在写入时，作答以独立 reply entry 落库），不得读工具结果本体。为什么：`ask_user_question` 契约要求模型「别等回答、继续干活」，若把过渡文提为答案区正文，作答恢复瞬间它会被降级进过程区，续写 thinking 阶段答案区再空白十几秒——用户视角即「答后正文闪烁」（V5.1 / V5.2；2026-11-03 真实模型复现，决策与修复见 [spec.md](../spec.md) 2026-11-03 段 e376a75）。
- **流式可见性用逐帧采样判定，不以单帧截图下结论**：视觉问题转几何判据——ego 以 50ms 逐帧采样数计数（「答案区→过程区位移事件 = 0」「正文可见但思考仍在流式」帧数 0、「忙但无指示器」帧数 0），判据记录在 [history/rendering-state-machines.md](../history/rendering-state-machines.md) S5 ego 验收与 [spec.md](../spec.md) 2026-10-21 段。闪烁是时间维度的缺陷，单帧截图既证明不了它存在、也证明不了它不存在。
- **改渲染先对照四台状态机的边界表**：交互卡片生命周期（S1）、工作分组开合（S2）、工具行身份（S3）、子智能体答案归属（S4）加回答区归属的现状与不变量在 [subsystems/rendering.md](../subsystems/rendering.md)；新改动不得引入转移矩阵中标过的非法转移（如 S2 的非边界帧改写开合、S5 的答案区降级）。
