# 提示词改动（prompt-changes）

改任何提示词 section、工具描述或 runtime-core 前先读本页；评审时逐条强制执行。section 清单与注入条件见 [runtime-system.md](../prompts/runtime-system.md)，快照机制见本页规则。

- **刷新快照并逐份审 diff**：改完必须 `npx vitest run tests/prompt-snapshot.test.ts -u` 刷新（团队快照在 [team.test.ts](../../tests/team.test.ts)，一并刷新），逐份审 diff——快照会机械记录任何改动，判断「这个 diff 是不是预期变化」是人 / agent 的责任，不是快照的责任。审完再跑 `npm run check`。纪律出处：[根 AGENTS.md](../../AGENTS.md) 约定与 [prompts-review-2026-11-04.md](../history/prompts-review-2026-11-04.md) 通用约束（「只允许出现本刀预期的变化」）；跳过审阅时快照会把退化记录得和改进一样合法，评审门形同虚设。
- **涉及行为变化必须配真实模型 live 场景并对照基线**：快照只证明「发了什么」，不证明「模型会怎么做」；凭据失败记「未执行」，不算通过（[根 AGENTS.md](../../AGENTS.md)）。真实案例：2026-10-28 提示词改造的刀 10 验收里，刀 6 新增示例「修一下→直接修」与 workflow fixture 的「直接实施」叠加，模型据此跳过待办协议——快照刷新后照样通过，靠 `test:live:workflow` 的 todo 断言（改造后 0/2）× 改造前基线（2/2）对照才拦下这处文案回归，修复为「→ 修复它」（`844cd79`）后双模式通过（[prompts-refactor-plan.md](../history/prompts-refactor-plan.md) 刀 10、[prompts-sources-and-integration.md](../history/prompts-sources-and-integration.md) 2026-10-28 验收记录、[spec.md](../spec.md) 2026-10-28 段）。
- **runtime-core ≤ 3,300 字符，棘轮只收紧**：由 [prompt-snapshot.test.ts:152](../../tests/prompt-snapshot.test.ts#L152) 把守，超限即门红；加规则先想删什么（[根 AGENTS.md](../../AGENTS.md)）。上限是护栏不是缩减目标，确需提额要在 PR 说明理由（[docs/AGENTS.md](../AGENTS.md) 字数预算）。
- **每条规则只留一个位置**：工具契约写在工具描述里，随工具可用性变化的规则写在动态 section 里，只有跨场景原则才进 [runtime-core.md](../../src/server/conversation/prompts/runtime-core.md)；唯一性由 [prompt-snapshot.test.ts](../../tests/prompt-snapshot.test.ts) 的 marker 断言把守。违例后果是两份文案各自漂移成矛盾：skills-policy 曾同一 section 一边「可装到全局」一边「用户级目录只读」，且刀 5 定下的「专用工具规则只写在工具描述」后来又被整行写回 runtime-core（均为 [prompts-review-2026-11-04.md](../history/prompts-review-2026-11-04.md) 问题 7 的实录）。
- **语言按 section 统一**：不做全局中英统一，但单个 section 内不得中英行交替，中文句子里不得拼接英文整句；工具名、参数名、代码保持英文标识符（[prompts-review-2026-11-04.md](../history/prompts-review-2026-11-04.md) 通用约束）。违例案例：`toolRouteInstruction` 的英文整句拼进中文 section，实际渲染出「调用 Call …directly.，」这类动词重复加错标点（同文件问题 1 / 刀 1）。
- **工具路由按 resolveToolRoute / toolRouteInstruction 渲染，不写死工具名**：只描述本请求真实可调用的工具，两个入口在 [tool-routing.ts](../../src/server/conversation/tool-routing.ts)；渲染中文 section 时传 `lang: 'zh'` 变体。违例案例：只读会话的 `exit_plan_mode` 描述与报错要求调用该会话根本不存在的 `enter_plan_mode`，同一请求里出现四种互相冲突的计划模式入口说法（[prompts-review-2026-11-04.md](../history/prompts-review-2026-11-04.md) 问题 2 / 刀 2）。
- **改了工具描述或 section 文案必须重跑 `npm run gen:docs`**：tool-catalog 与 section-catalog 由代码生成，不重生则 `verify:docs` 报 first-diff，新增工具不进目录会被完整性守卫直接拒绝（[docs/AGENTS.md](../AGENTS.md) 生成目录规则）。
