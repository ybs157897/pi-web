# Windows 与 shell（windows-shell）

改 shell / 搜索工具、CLI spawn 或任何 Windows 路径处理前先读本页；评审时逐条强制执行。完整能力矩阵、缺陷编号（W1–W15）与待实机清单见 [windows-support.md](../windows-support.md)。

- **工作区内容搜索与文件发现不走 PowerShell 枚举**：内容搜索用 grep 工具（原生 ripgrep）、文件发现用 glob 工具；递归 `Get-ChildItem | Select-String` 在 spawn 前被 FORBIDDEN 拒绝并指向 grep（[windows.ts:40](../../src/server/tools/shell/windows.ts#L40) 的拦截、[windows.ts:146](../../src/server/tools/shell/windows.ts#L146) 的工具描述同此约定）。PowerShell 枚举自身的坑也是理由之一：`-Include` 需配 `-Path` 通配或 `-Recurse` 才生效、通配语义与 `-LiteralPath`（按字面取路径，供含 `[`/`*` 的路径使用，见 [windows.ts:179](../../src/server/tools/shell/windows.ts#L179) 的 `Set-Location -LiteralPath`）不同——在命令行里手搓枚举既慢又易错，递归扫描会静默走进生成物目录。
- **spawn 用显式二进制 + 参数数组，不用 `shell: true`**：`shell: true` 在 Windows 经 cmd.exe 解释整行，`.cmd` / `.bat` 垫片路径同样构成命令注入面。仓库先例：WeTrack CLI 的 spawn 去掉了 `shell: true`——裸命令名按 `PATH` / `PATHEXT` 解析成真实路径（`spawn` 自己只补 `.exe`），`.cmd` / `.bat` 显式经 `cmd.exe /d /s /c` 并传「整行预加引号 + `windowsVerbatimArguments: true`」的字符串，argv 只在一处拼接（[wetrack.ts:163](../../src/server/automation/wetrack.ts#L163) 起的 `findOnPath` / `resolveCommand` / `batchCommandLine`；决策记录见 [spec.md](../spec.md) 2026-10-31 段）。
- **退出码是判据：pwsh 不注入错误偏好，exit 0 + 空输出是合法成功**：pwsh 包装脚本设 `$ErrorActionPreference='Continue'`（[windows.ts:50](../../src/server/tools/shell/windows.ts#L50)）并显式传播 `$LASTEXITCODE`（[windows.ts:53](../../src/server/tools/shell/windows.ts#L53)），所以 cmdlet 的非终止错误不改变裁决；共享 runner 里 exit 0 即使输出为空也按成功结算，非零退出码才是 `isError`（[runner.ts:261](../../src/server/tools/shell/runner.ts#L261) 起）。grep 族退出码 1 判为成功「无匹配」（[common.ts:45](../../src/server/tools/shell/common.ts#L45)）。不要把「输出为空」当错误处理——唯一例外是契约要求非空：JSON CLI 的空输出违反契约才是错误（[wetrack.ts:205](../../src/server/automation/wetrack.ts#L205)）。
- **参与散列 / 比较的 Windows 路径先归一**：大小写——Windows 文件系统大小写不敏感，参与散列前转小写（memory 先例：win32 平台对规范化路径 `toLowerCase()` 再散列，[store.ts:32](../../src/server/memory/store.ts#L32)）；分隔符——HTTP 协议里的资源路径要求 `/` 并拒绝 `\`，测试断言不要写死 POSIX 分隔符（[skills.test.ts:71](../../tests/skills.test.ts#L71) 的 `/` 分隔断言在 Windows `path.join` 产出 `\` 时必失败，[windows-support.md](../windows-support.md) X8）。
- **shell 类改动不能只在 macOS 验证**：Windows 是有条件支持，macOS 上 `npm run check` 全绿不能证明 Windows 可交付；[根 AGENTS.md](../../AGENTS.md) 约定此类改动须声明 Windows 侧验证路径，[windows-support.md](../windows-support.md) 标为「待实机」的项目必须在 Windows 10/11 上复测才能视为已验证。
